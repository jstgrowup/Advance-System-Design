# Partitioning Demo on AWS RDS

- Created an RDS instance and connected to it locally.

## Create the Database and Table

```sql
show databases;
create database test
use test
CREATE TABLE bookings {
  booking_id INT PRIMARY KEY,
  user_id INT,
  bookin_date DATE,
  status VARCHAR(50)
  PRIMARY KEY (booking_id,booking_date)
}
```

## Partition Query

- Here is the partition query.
- Partition the table via range-based partitioning, then we tell which particular property to use. Here, it is the booking date.

```sql
PARTITION BY RANGE (YEAR(booking_date)*100+MONTH(booking_date))(
  PARTITION p202301 VALUES LESS THAN (202301)
  PARTITION p202302 VALUES LESS THAN (202302)
  PARTITION p202303 VALUES LESS THAN (202303)
  PARTITION p202304 VALUES LESS THAN (202304)
  PARTITION p202305 VALUES LESS THAN (202305)
  PARTITION p202306 VALUES LESS THAN (202306)
  PARTITION pmax VALUES LESS THAN MAXVALUE
)
```

## Changing the Partition Logic

- You have to make sure the partition logic is written while creating the table itself.
- If you need to change the partition logic, then you have to back up the data and create the table again, or else you can use `TRUNCATE TABLE`.

> 💡 **Added explanation:**
>
> - The `PARTITION BY` clause goes at the end of the `CREATE TABLE` statement, after the closing `)`.
> - `TRUNCATE TABLE` removes all the rows but keeps the partition definition.

## Insert Data

```sql
INSERT INTO bookings (booking_id,user_id,booking_date,status)
VALUES(1,101,'2023-01-15','confirmed'),(2,102,'2023-01-20','canceled')
```

- Now, you don't have to care about the partition logic. MySQL will handle it automatically by itself.

> 💡 **Added explanation:** each partition holds values `LESS THAN` its number, so the January 2023 rows (value 202301) land in `p202302`.

## Query a Partition

```sql
select * from bokings partition(p202303)
```

- When we query, we don't have to handle which partition to search. MySQL will handle that automatically.
- This whole thing is called row-based partitioning.

> 💡 **Added explanation:** the table is named `bookings`, so `bokings` in the query above is a typo.
